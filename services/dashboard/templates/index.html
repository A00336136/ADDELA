Detailed architecture flow

One request, end to end — entirely on-premise. The gateway is the only ingress; the four detectors score in parallel; fusion decides; the protected model answers only on ALLOW; every decision is logged, and that log feeds the offline RQ2 drift analysis.

How we test it — our system vs the LlamaFirewall baseline

LlamaFirewall is not part of ADDELA. It is Meta's ready-made guardrail, used only as a yardstick. The same test prompts go through both systems; we compare who blocks real attacks while allowing safe requests.

The result, in one line: ADDELA's four layers catch threat types (e.g. harmful content) that LlamaFirewall's on-premise scanners miss — so it blocks more real attacks at the same false-alarm rate. That broader, layered coverage is the adaptive defence-in-depth the project title promises.

How to read this

One Ollama, three jobs. A single native Ollama runtime on your Mac hosts all three models (green box). L1 and L3 are guardrails that consult a model as a classifier — L1 asks the small llama3.2:3b a yes/no moderation question (cheap, runs on every prompt); L3 reads llama-guard3:8b's safe/unsafe verdict. L2 and L4 run entirely in-container (no LLM). The prompt reaching these classifiers is the inspection — not a leak.

gemma4:12b-mlx is the protected model — the capable assistant that actually answers the user. It is reached only after fusion returns ALLOW, which is the whole point: no input touches the protected model until the defence has cleared it.

Every decision is logged on-premise (append-only), and that log is the training stream for RQ2: a CUSUM change-point detector watches the fused-risk distribution and recalibrates fusion weights/thresholds as threats drift — the amber feedback loop.

Combiners (RQ1) — what every bar in Evaluation 1 means, and where its number came from

The four detectors are deployed services. The three composition rules are three ways of combining the same four captured scores — only the noisy-OR is deployed; the union and the learned stacker exist solely as offline comparisons, which is why they are not services and not in the architecture diagram. LlamaFirewall is an external baseline in its own container.

How these numbers are produced
  1. Every prompt is run once through the live gateway; the four per-layer scores are captured to eval/scores.json.
  2. The three composition rules are applied to those identical captured scores, so any difference is caused by the rule alone.
  3. Scoring uses leakage-safe 5-fold cross-validation: the threshold is fitted on the training fold and measured on the held-out fold.
  4. LlamaFirewall is driven over the same 67 prompts from the Comparison tab; its decisions are stored in data/dashboard/compare.json.
